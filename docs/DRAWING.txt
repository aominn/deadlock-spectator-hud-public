観戦・リプレイ中の描画 — 0.6.0

準備と操作
1. 「準備する」の完了後、HUDを有効にしてツールからゲームを起動。
2. 管理画面で「線を描く」にチェック。表示キーを選択する。
3. 観戦・リプレイを前面にし、F8（初期設定）でツールバーを表示/非表示。
   競合時はF9/F10/Ctrl+Shift+Dへ変更できる。
4. 表示直後から描画できる。ツールバーの外をドラッグすると線を描く。
   描画中もツールバーの色・太さ・道具・消去・「観戦へ」を操作できる。
5. 「観戦へ」かEscで線とツールバーを残し、ゲームのUI・カメラ操作へ戻る。
6. F8で非表示にするときも線は残し、入力は観戦操作へ戻す。
   再表示も描画から始まる。「観戦へ」かEscでゲーム操作に戻れる。
7. 線を消す場合は「消去」。右クリックまたは「戻す」で1本戻す。


ツールバー
・画面全体に描画。ミニマップ上にもそのまま描ける。範囲の切替はない。
・線は画面上の位置に固定され、ミニマップが移動・拡大しても追従しない。
・ペン / 矢印：自由線または始点と終点で矢印。
・白 / 水色 / 赤 / 黄、細3px / 太8pxの2段階（1920px幅基準）。
・線の見本と選択枠で現在の太さを示す。変更はこれから描く線へ反映。
・取り消しと全消去。描画操作とツールバーの表示は別に切り替える。
・タイトルバーのないチャコールのパレット。左端の持ち手をドラッグして移動できる。
・移動位置と色・太さ・道具はツールを開いている間保持する。管理ツールの×では線も消す。

動作
線は利用者のPC内だけで扱い、保存・他プレイヤーへの配信はしない。
入力はWindowsの専用描画面で受け取り、線はゲーム内HUDへも渡す。
ゲーム内ミニマップの既存ペンやピンの操作設定を書き換えない。
自動でリプレイを停止・再開しない。解説前に必要なら自分でポーズする。
ウィンドウ/ボーダーレス表示向け。排他的フルスクリーンは動作保証しない。
ライブでは描画中も試合は進む。描画を終了してからカメラを動かす。

保持と解除
ポーズしてゲーム時刻が同じでも、同じ観戦の確認が続く間は保持する。
通常モード、ロビー/対戦、試合切替、巻き戻し、明らかな時刻ジャンプ、
管理ツール終了では消去する。別アプリへの切替とEscでは操作だけ解除する。
通信確認中は入力と画像表示を止め、同一試合・時刻の継続を確認できたら線を戻す。
画面が隠れていた時間と整合しない進行や別セッションなら保持した線を破棄する。
画面サイズ変更では操作を止め、表示キーで開くと新サイズに合わせて描画を再開できる。
最大128本、合計4096点。超過時は古い線から整理し、1本が上限に達したらそれ以上点を増やさない。

配信
線をゲーム内HUDに表示するため、ゲーム画像への合成が可能な構成。
OBS等の各キャプチャ方式での通し確認は未実施。ツールバーは外部のウィンドウ。
画面キャプチャではツールバーも映り得るため、配信前に取得範囲を確認する。

実装と資料
engine/drawing_hud.py：状態・上限・画像生成、manager/InkModel.cs：線のモデル。
manager/DrawingOverlay.cs：操作窓・開始キー、spectator_probe.js：ゲーム内画像表示。
Windows標準APIのみ。入力フック、DLL注入、Steam保存設定の編集は追加しない。
ゲーム側のカーソル切替とWindows側の描画操作窓は別の仕組み。F8表示時にはWindowsの操作先をツールバーへ移す。
ゲーム側のhud_free_cursorやキー割り当てを自動変更しない。


描画時はツール側が入力を受けます。フリーカメラでも構図を維持して描画できますが、ゲームが非前面になるため環境によってFPSが下がります。「観戦へ」またはEscでゲーム操作へ戻ります。

描画開始前に、管理画面の「線を描く（観戦・リプレイ中のみ）」を有効にしてください。
このチェックは管理画面を開くたびに入れ直します。F8はゲーム画面が前面で、観戦/リプレイの情報を取得できている間に反応します。
ライブ観戦も対象です。接続待ちや配信404の間は、まだ観戦画面として開始されていないため描画は開始しません。
Drawing is available in live spectating and replays. Enable the drawing checkbox each time the manager opens. F8 requires the game in the foreground and an active spectator/replay session; a waiting or unavailable broadcast is not an active session.
